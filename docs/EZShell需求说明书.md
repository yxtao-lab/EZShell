## 1. 概述

### 1.1 产品定位

EZShell 是一款**类 Termius** 的跨端 SSH 运维工具，同时提供 **SaaS 会员平台**。  
客户端负责主机连接、终端、SFTP、配置管理；云端负责账号、会员权益、配置同步与运营管理。

一句话：**让个人与团队更轻松、更安全地管理远程服务器，并通过会员制实现商业化。**

### 1.2 目标用户

| 角色 | 诉求 |
|---|---|
| 个人开发者 / 运维 | 多主机管理、快速连接、片段复用、配置备份 |
| 兼职/自由职业者 | 多设备同步、专业档权益 |
| 小团队 Leader | 席位管理、共享主机组、统一开通 |
| 平台运营 | 用户管理、套餐与订单、数据看板 |

### 1.3 产品目标

1. 提供功能全面、操作友好的 SSH 客户端（桌面 + 移动）。  
2. 提供可商业化的 SaaS：注册登录、会员付费、权益控制、管理后台。  
3. 全中文界面，多端视觉与交互风格统一。  
4. 支持主流配置迁移（OpenSSH、MobaXterm 等）。

### 1.4 非目标（首期明确不做）

- 完整跳板机（Bastion/ProxyJump）链路（仅预留字段）  
- 本地系统 Shell（仅远程 SSH）  
- 团队实时协作编辑、IM  
- 自研云主机 / 云厂商控制台  
- 完整发票税务系统（可后期扩展）

## 2. 技术架构需求

### 2.1 总体约束

| 项 | 要求 |
|---|---|
| 包管理 | **仅 pnpm**（禁止混用 npm/yarn） |
| 仓库形态 | **pnpm monorepo** |
| 桌面端 | **Electron**（建议 Vue3 + TypeScript） |
| 移动端 | **uni-app**（建议 Vue3 + TypeScript） |
| 管理后台 | Web（Vue3 + TypeScript） |
| 后端 API | Node.js（建议 NestJS 或 Fastify）+ TypeScript |
| 数据库 | PostgreSQL |
| 缓存 | Redis（会话、限流、短期权益缓存） |
| 语言 | 界面文案、代码注释、提交说明使用**中文** |

### 2.2 推荐目录结构

```text
ezshell/
  package.json
  pnpm-workspace.yaml
  apps/
    desktop/                 # Electron 客户端
    mobile/                  # uni-app 客户端
    api/                     # SaaS API
    web-admin/               # 运营/用户管理后台
    web-portal/              # 官网 / 定价 / 登录（可选，可二期）
  packages/
    shared/                  # 类型、枚举、错误码、备份格式、校验
    core/                    # 主机/密钥/片段/导入导出等纯业务逻辑
    ui-tokens/               # 颜色、间距、圆角、字体 token
    sdk/                     # 调用 API 的 TypeScript SDK
  docs/
    EZShell需求说明书.md
  README.md
```

### 2.3 端能力分工

| 端 | 职责 |
|---|---|
| desktop | 完整 SSH/SFTP/转发能力；多标签；本地安全存储；登录会员 |
| mobile | 主机连接、终端、SFTP、片段；触控友好；登录会员与同步 |
| api | 认证、套餐、订单、同步、权益校验、管理接口 |
| web-admin | 用户、会员、订单、套餐、公告、基础数据 |
| shared/core/sdk | 消除多端重复实现，保证模型一致 |

### 2.4 跨端一致性原则

1. 业务模型（主机、密钥元数据、片段、转发、备份 JSON）在 `shared/core` 统一定义。  
2. 视觉 token 统一，允许平台控件差异，但信息架构与主色、终端风格一致。  
3. 桌面：左侧导航 + 右侧多标签会话。  
4. 移动：底部导航 + 全屏会话。  
5. 关键路径（连接、输密码、导入导出）两端均可达、文案一致。

## 3. 客户端功能需求

### 3.1 主机与分组

#### 功能说明

- 主机 CRUD：名称、主机地址、端口、用户名、认证方式、标签、备注。  
- 分组：创建/重命名/删除；删除分组不删除主机（主机变为未分组）。  
- 列表支持搜索（名称/地址/用户/标签）与分组筛选。  
- 跳板机字段预留（`jumpHostId`），首期不实现链路。  
- 首次连接展示主机密钥指纹，用户确认后本地记忆。

#### 验收要点

- 可完成新增、编辑、删除、连接。  
- 非法端口（非 1–65535）与空必填项有明确中文提示。

### 3.2 密钥管理

#### 功能说明

- 导入 OpenSSH 私钥（至少支持 Ed25519、RSA）。  
- 本地生成 Ed25519 密钥。  
- 查看/复制公钥、显示指纹。  
- 私钥可带口令；私钥与口令存系统安全存储。  
- 主机可绑定密钥进行公钥认证。

#### 验收要点

- 生成与导入后可用于连接。  
- 删除密钥时解除主机绑定关系。

### 3.3 SSH 终端

#### 功能说明

- 多会话：桌面标签页；移动会话列表/切换。  
- 连接 / 断开 / 重连。  
- 终端渲染、滚动、复制粘贴。  
- 字体与配色预设（深色终端友好）。  
- 连接状态可视化（连接中/已连接/断开/失败）。  
- 错误信息中文可读（如认证失败、超时、主机不可达）。

#### 密码输入（关键体验，必须）

| 场景 | 行为 |
|---|---|
| 未保存密码且服务器要求密码 | 弹窗输入密码 |
| 勾选「记住密码」 | 写入安全存储，下次自动使用 |
| 认证失败 / 密码错误 | 会话工作区提示条 +「输入密码」按钮 |
| 工具栏 | 提供「输入密码并重连」入口 |
| 取消输入 | 连接中止，不崩溃 |

#### 验收要点

- 不出现「无密码直接 AuthAbort 且无法补救」的死路。  
- 从 MobaXterm 导入的主机（通常无密码）可当场输入密码完成连接。

### 3.4 SFTP

#### 功能说明

- 目录浏览、上级目录、刷新。  
- 上传、下载、重命名、删除。  
- 与当前 SSH 会话关联（复用连接或独立通道，实现可选，体验上对用户透明）。

#### 验收要点

- 在已连接会话中可完成上传下载。  
- 未连接时给出明确提示。

### 3.5 命令片段

#### 功能说明

- 片段 CRUD，支持分类。  
- 变量占位：`{host}` `{user}` `{name}` `{port}`。  
- 一键发送到当前活动终端（可自动补换行）。

#### 验收要点

- 无活动会话时提示「当前没有活动终端会话」。  
- 变量按当前会话主机正确替换。

### 3.6 端口转发

#### 功能说明

- 规则类型：本地转发（Local）、远程转发（Remote）。  
- 字段：名称、关联主机、绑定端口、目标主机、目标端口。  
- 启停状态展示；停止后释放资源。

#### 验收要点

- 本地转发可在本机访问到远端目标（测试环境验证）。  
- 远程转发失败时给出权限/配置类中文提示。

### 3.7 导入导出

#### 3.7.1 EZShell 备份

- 导出内容：主机、分组、片段、转发规则；可选包含密码与密钥。  
- 文件名建议：`ezshell-backup.json`；加密包可用 `ezshell-backup.ezb`。  
- 可选 AES（或同等强度）口令加密。  
- 导入模式：合并 / 覆盖。

#### 3.7.2 OpenSSH Config

- 解析常见 `Host` 块（忽略通配 `*`/`?`）。  
- 导入 HostName / User / Port 等到主机列表。

#### 3.7.3 MobaXterm（必须）

- 支持 `.mobaconf` / `.mxtsessions` / 相关 ini。  
- 解析 `[Bookmarks]`、`[Bookmarks_N]` 与 `SubRep` 分组。  
- **仅导入 SSH 会话（协议码 `#109#`）**；跳过 RDP / FTP / SFTP 书签 / WSL 等。  
- 同「主机 + 端口 + 用户」去重。  
- 尽量导入 known_hosts 指纹（若文件含 SHA256 指纹段）。  
- Moba 密码为专有加密，**无法还原**；导入后备注提示用户自行填写密码。  
- 文件编码兼容：UTF-8 失败时回退（如 Latin1/系统 ANSI），保证 ASCII 会话字段可解析。

#### 验收要点

- 用户真实 MobaXterm 导出文件可导入多台 SSH 主机。  
- 加密备份可在正确口令下恢复；错误口令有明确失败提示。

### 3.8 设置与关于

- 导入导出入口集中在「设置」。  
- 关于页展示产品名 EZShell、平台支持说明、版本号。  
- 账户/会员入口（登录态、套餐、同步开关）。

## 4. SaaS 与会员需求

### 4.1 账号体系

| 能力 | 说明 |
|---|---|
| 注册 | 邮箱或手机号 + 密码（首期至少一种） |
| 登录 | 签发 Access Token + Refresh Token |
| 登出 | 作废当前刷新令牌 |
| 个人中心 | 昵称、账号、会员状态、到期时间 |
| 设备管理 | 查看已登录设备；支持踢下线（Pro/Team 可优先） |
| 安全 | 密码哈希（argon2 或 bcrypt）；传输 HTTPS |

### 4.2 会员套餐（可配置，建议默认三档）

| 档位 | 建议权益（可后台调整数值） |
|---|---|
| Free | 本地主机上限（如 5）；无云同步；基础终端/SFTP |
| Pro | 更高/不限主机数；云同步；多设备；优先支持 |
| Team | Pro + 多成员席位 + 共享主机组 + 管理权限 |

#### 订阅规则

- 周期：月付 / 年付。  
- 状态：未开通 / 有效 / 宽限期 / 已过期。  
- 到期：进入降级（回 Free），本地数据不删；云同步停止拉取/推送（保留只读导出可选）。  
- 权益校验：**服务端权威**；客户端仅展示，不可只靠本地破解。

### 4.3 订单与支付

#### 首期可选两档实现（实施前确认）

**方案 A（推荐首期）**：管理后台手动开通/延期 + 支付接口抽象预留。  
**方案 B**：接通微信/支付宝（国际可预留 Stripe）。

#### 无论 A/B，系统需具备

- 套餐 SKU、价格、周期配置。  
- 订单创建、支付状态机（待支付/已支付/失败/关闭）。  
- 支付回调验签（方案 B）。  
- 开通成功后即时刷新权益。

### 4.4 云同步（按会员解锁）

#### 可同步对象

- 主机元数据、分组、片段、转发规则。  
- 密钥/密码：**默认不强行上云**；若上云必须加密，且产品文案明确告知。

#### 安全要求（二选一，建议默认端到端）

1. **端到端加密（推荐）**：用户主密码/同步口令派生密钥，服务端存密文不可读。  
2. **服务端加密**：KMS/应用层加密，运维可控但责任更高。

#### 冲突策略

- 以「字段级最后修改时间」或「整对象版本」合并。  
- 冲突时客户端提示，支持「保留本地 / 使用云端」。

### 4.5 用户管理平台（web-admin）

| 模块 | 需求 |
|---|---|
| 用户管理 | 列表、搜索、详情、封禁/解封、重置密码 |
| 会员管理 | 开通、改档、延期、取消；查看到期时间 |
| 订单管理 | 流水查询、状态筛选 |
| 套餐配置 | 价格、周期、权益开关与额度 |
| 公告 | 客户端可拉取的公告/强制更新提示 |
| 数据看板 | 注册量、付费用户数、活跃设备数（基础即可） |
| 审计 | 管理员关键操作日志 |

#### 权限

- 首期可做「超级管理员」单角色。  
- 预留角色权限表结构，便于二期拆分运营/财务角色。

## 5. 信息架构与交互需求

### 5.1 桌面端（Electron）

```text
侧栏：主机 | 密钥 | 片段 | 端口转发 | 设置/账户
主区：列表/表单
会话区：多标签（终端 | SFTP）
```

- 快捷键建议：`Ctrl+T` 聚焦会话，`Ctrl+W` 关闭当前会话。  
- 空状态引导「添加主机 / 导入配置」。

### 5.2 移动端（uni-app）

```text
底栏：主机 | 密钥 | 片段 | 我的（设置/账户）
主机：点击连接；长按更多操作
会话：全屏终端；可切 SFTP
```

- 大触控目标；减少深层嵌套。  
- 认证失败顶部条「输入密码」。

### 5.3 视觉风格

- 全中文。  
- 深色终端优先；主色建议青绿系，避免千篇一律的紫白渐变风。  
- 列表清晰、卡片克制、状态色明确（成功/警告/错误）。  
- 两端品牌名均展示 **EZShell**。

## 6. 数据与安全需求

### 6.1 客户端本地数据

| 数据 | 存储 |
|---|---|
| 主机/分组/片段/转发元数据 | 本地 DB 或结构化存储 |
| SSH 密码、私钥、私钥口令 | 系统安全存储（钥匙串 / Credential / Keystore 等） |
| 主机指纹 | 本地与主机关联保存 |

### 6.2 服务端数据（核心实体）

- User、DeviceSession  
- Plan、Subscription、Order、PaymentEvent  
- SyncVault / SyncObject（密文）  
- AdminUser、AuditLog、Announcement  

（具体表结构在技术方案阶段细化。）

### 6.3 安全基线

1. 全站 HTTPS。  
2. 密码不可逆哈希。  
3. JWT 密钥、支付密钥仅环境变量。  
4. API 鉴权 + 会员权益中间件 + 限流。  
5. 管理后台独立鉴权，操作审计。  
6. 客户端禁止日志打印明文密码/私钥。

## 10. 用户故事（节选）

1. 作为运维，我希望导入 MobaXterm 配置，快速迁移主机列表。  
2. 作为用户，我连接未存密码的主机时，希望弹窗输入并可记住。  
3. 作为用户，我认证失败后希望在会话页再次输入密码重试。  
4. 作为 Free 用户，我希望先免费用起来，再决定是否开通 Pro。  
5. 作为 Pro 用户，我希望手机与电脑同步主机与片段。  
6. 作为管理员，我希望给用户手动开通一年 Pro。  
7. 作为用户，我希望加密导出全部配置，换电脑后恢复。

## 12. 实施阶段建议

| 阶段 | 内容 | 产出 |
|---|---|---|
| P0 | monorepo + shared/sdk + API 认证/套餐骨架 | 可登录的空壳平台 |
